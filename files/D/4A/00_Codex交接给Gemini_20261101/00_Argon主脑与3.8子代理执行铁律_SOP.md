## 一、对之前 3.8 历史事故的根因复盘（严禁重犯）

1. **价格口径混用事故（最严重）**：
   - **3.8 旧错**：把《2026 总表》里另收运费（`N=4.99` / `B=9.99` / `H=11.99` / `2H=22.99`）的 MFN 裸价，直接刷进 FBA 包邮活跃链接（导致 `5082` 从 \$11.99 跌至 \$5.99、`004` 从 \$15.99 跌至 \$9.49 等 37 处普通价异常下跌）。
   - **铁律 1**：**子代理严禁自行计算或修改任何价格字段**（普通价、Sale 促销价、B2B 企业价、数量阶梯、最低允许价、Coupon）。所有价格变动必须由 Argon 主脑逐 SKU 核对【当前 FBA 费用 + FOB + 历史成交价 + 叠加最深折扣】并获用户批准后方可执行。
2. **全量变体大表盲刷事故**：
   - **3.8 旧错**：一次性生成 861～961 行的《15 大家族 / 21 大家族全量变体清洗表》，为了消除报错盲目填充 `Neon Assorted`、`Classic Assorted`、错误的 `size` / `number_of_items`，不仅没修好错误，反而污染了在售 FBA 商品的属性（如把 `4A 039` 橙粉装刷成 `Neon Assorted` 触发 `8541`）。
   - **铁律 2**：**彻底废止“全店大表全量覆盖”**。每次上传必须遵循**最小字段原则（Minimal-Cell Partial Update）**：只包含目标 SKU、精确身份标识列（`C/D/E/L/M`）及唯一获批修改的那 1～2 个属性列，其余列必须 100% 留空！
3. **虚假“已完成/已生效”汇报事故**：
   - **3.8 旧错**：把“文件已生成”、“上传显示完成”或“工单已发送”直接向用户汇报成“前台已恢复、已合并成功、买家已可买”；或者把候选图包当成“已批准上传”。
   - **铁律 3**：**严格执行四层事实分离口径**：
     - **L1 已提交（Submitted）**：仅取得批次号或 Case ID；
     - **L2 回执接受（Receipt Accepted）**：官方 Processing Summary 显示 `SUCCESS`（注：`SUCCESS (OTHER ERROR)` 需拆解具体错误码，既不等于整行失败，也不等于前台已发布）；
     - **L3 卖家后台回读（Seller Editor Readback）**：重新打开独立编辑页确认新值已落库且目标报错码消失；
     - **L4 买家前台可买验收（Buyer PDP Live & Buyable）**：前台详情页展示、购物车按钮、配送地址（如纽约 `10001`）实际可结算。
     - **未达到哪一层，就如实标为 `Pending`，绝不跳层报喜！**
4. **盲抄目录消错与乱动家族事故**：
   - **3.8 旧错**：遇到 `8541` 目录冲突就盲目照抄 Amazon 目录错误值，或企图通过删 SKU、清空父体来强行修家族。
   - **铁律 4**：**无实物证据不改目录属性；严禁删有货 SKU 或擅动父子关系**。修改 `color` / `size` / `number_of_items` / `manufacturer` / `UPC` 前，必须在 `D:\4A\印刷用图片` 或官方总表中找到实物包装/腰封条码证据。

## 三、3.8 子代理派发与验收标准流程（Brain -> Worker Protocol）

1. **只派发确定性微任务**：
   - 每次给 3.8 子代理的任务必须明确限定：**输入文件列表、目标 SKU/ASIN 集合、只读/写入边界、输出 JSON/报告路径**。
2. **子代理无权直接提交线上高危更改**：
   - 3.8 子代理不得自行在卖家后台点击上传提交、不得自行改价、不得自行发送客服工单、不得自行修改共享运费模板。
3. **主脑独立 QA 闸门**：
   - 子代理生成的任何数据或候选表格，必须经 Argon 主脑执行独立脚本校验（核对非空单元格数量、精确列名、SHA-256 哈希、ZIP 内部 XML 结构完整性）后，方可交付或执行。
